05 · UART debugging · 01

Serial bytes are not commands yet

The endpoint receives bytes, frames a packet, checks integrity, then validates a command before allowing any effect.

Explore the reasoning

COBS gives delimiter-safe framing; the CRC detects corruption within the checked packet. Neither a delimiter nor a plausible opcode alone authorizes execution.

05 · UART debugging · 02

A lost reply must not repeat a step

An identical immediate retry replays the cached response. It does not assert a new command and execute STEP a second time.

The retry arrow reaches the cache comparison; it does not create a second STEP.

Explore the reasoning

The comparison uses the complete decoded request, not just its sequence number or encoded byte spelling. This is bounded duplicate suppression for the last completed exchange.

05 · UART debugging · 03

The same sequence can still conflict

A retry with the same sequence but different content returns SEQUENCE. It leaves the completed cache and emulated state unchanged.

Identical

Replay the retained response.

Conflicting

Return SEQUENCE without command effects.

Reset

Core reset preserves the cache; global reset invalidates it.

Explore the reasoning

Ask why core reset cannot simply erase transport history: if reset’s reply is lost, the host still needs a safe retry of that completed exchange.

05 · UART debugging · 04

Loading is a transaction

LOAD_BEGIN invalidates the image and resets the core. LOAD_END requires every byte and checks CRC32 by reading actual ROM storage before publishing valid PAUSED state.

Explore the reasoning

A checksum over received bytes alone could miss a storage-write defect. The endpoint validates the resulting image. No execution should observe a half-loaded ROM.

Source: Core and storage integration

05 · UART debugging · 05

STEP ends at instruction completion

The endpoint pauses on accepted instruction completion, before following-edge retirement publication finishes. An interrupt-entry record alone does not complete STEP.

Explore the reasoning

Transport logic keeps running during pause. An already STOPped STEP returns immediately without consuming time; a debugger must report actual state rather than invent an instruction.

Source: STEP completion boundary

05 · UART debugging · 06

Separate transport from execution proof

A preloaded Intel-model run proves execution of those bytes. A real-UART load/readback run additionally exercises the transport path.

Preload

Validate image and model initialization, then execute.

UART path

Send, store, read back and verify through the actual endpoint.

Board

Physical serial wiring and hardware remain separate evidence.

Explore the reasoning

Preload is useful for bounded simulations but cannot establish that serial upload worked. This distinction makes a test’s claim match the route it actually exercised.

Source: Execution modes
