09 · Console and cartridge · 01

The console executes; the cartridge supplies

A Game Boy is a console working with a removable program-and-data system. The CPU remains in the console, even when the cartridge contains control logic.

Explore the reasoning

PPU means picture processing unit; APU means audio processing unit; OAM holds object attributes. These describe original console functions, not a claim that our FPGA implements every function. Cartridge RAM may use a battery to retain saves. An RTC is a real-time clock. This functional split does not mean every console or cartridge literally has one PCB.

09 · Console and cartridge · 02

One CPU address can reach different storage

The 16-bit CPU address space is 64 KiB. Cartridge storage can be larger because a controller chooses which bank answers a read.

CPU address (hex) Owner Meaning
0000–3FFF Cartridge Lower 16 KiB ROM window, usually bank 0
4000–7FFF Cartridge Upper 16 KiB ROM window, mapper-selectable
8000–9FFF Console 8 KiB VRAM
A000–BFFF Cartridge Optional RAM or mapped peripheral
C000–DFFF / FE00–FE9F Console 8 KiB WRAM / 160 bytes OAM
FF00–FF7F / FF80–FFFE Console I/O registers / 127 bytes HRAM
Explore the reasoning

This selected-region table omits echo RAM, unusable space and the interrupt-enable byte at FFFF. Reads in 0000–7FFF obtain ROM data; on mapper cartridges, writes in that range configure controller registers instead of overwriting ROM. The header at 0100–014F describes cartridge requirements. It does not build an MBC or turn the console CPU into one.

09 · Console and cartridge · 03

Switch the window, not the bytes

Worked example: 64 KiB = four 16 KiB banks. In MBC1 mode 0 with upper bank bits zero, writing 02 to address 2000 selects bank 2 for the upper window.

Explore the reasoning

All numbers in the diagram are hexadecimal image offsets or CPU addresses, as labeled. The intra-bank offset is 4567−4000=0567. A real ROM chip keeps the same bytes; MBC outputs select another address. This introductory example deliberately omits mode 1 remapping, RAM banking, alternative wiring, ignored address bits and bank-zero aliases. MBC1 is not a simple unrestricted four-bank selector for every register value.

09 · Console and cartridge · 04

Cartridge features vary by design

An MBC is a memory bank controller, not a second gameplay CPU. The chip and board wiring determine which storage and peripherals exist.

Example Banking role Optional or special hardware
ROM-only No bank-selection controller Simple program/data cartridge
MBC1 ROM/RAM modes and wiring-dependent bank bits RAM and battery on equipped boards
MBC3 7-bit ROM-bank selection RAM; RTC-equipped variants can keep time on battery
MBC5 9-bit ROM bank: up to 512 ×16 KiB =8 MiB RAM/battery; rumble on equipped boards
MBC7 Specialty cartridge controller Two-axis accelerometer and 256-byte EEPROM
Explore the reasoning

A battery retains volatile RAM or powers a clock; it is not extra address capacity. EEPROM retains data without battery-backed SRAM. MBC5 rumble consumes a RAM-bank control bit. MBC1 standard 512 KiB ROM/32 KiB RAM and alternate 2 MiB ROM/8 KiB RAM wiring are different combinations, not simultaneous independent maxima. Actual compatibility depends on each implemented feature and timing.

09 · Console and cartridge · 05

The FPGA hosts both sides of the boundary

Our virtual cartridge replaces a physical ROM board with loaded bytes and the supported address behavior. Loading an image and executing a mapper write are different operations.

Explore the reasoning

Current dmg-direct-v1 starts without a mapped boot ROM. It does not infer mapper implementation from a header. Open #307 separately specifies a bounded 64 KiB MBC1/no-RAM profile; that is planned, not delivered by this lesson. APU/audio output and universal cartridge compatibility are not claimed. Physical monitor/control acceptance is a separate project gate.

09 · Console and cartridge · 06

Memory capacity is only one requirement

DE10-Lite has 64 MB of external SDRAM and separate on-chip M9K blocks. A large chip on the board does not automatically provide a larger supported cartridge.

Explore the reasoning

Terasic lists 1,638 Kbit of on-chip M9K memory separately from external SDRAM. Logical payload bytes and allocated RAM blocks differ because geometry and ports constrain packing. A larger cartridge needs storage, address mapping, a loader and proven timing together. Larger SDRAM-backed images remain future/unimplemented here; no current fit utilization or capacity estimate is an acceptance result. Ask: who executes, who supplies bytes, which window changes, and which hardware features are actually supported?
